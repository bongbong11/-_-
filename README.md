## ✨ 한눈에 보기

캐릭터가 계속 망설이거나, 같은 대화를 반복하거나, 갑자기 모든 걸 알아맞히거나, 사건을 시작해 놓고 진행하지 않는 일이 잦다면 씬판독기가 그 사이를 정리해 줍니다.

- 🎬 **자동 전개** — 관계·사건·NPC·직접 반응 중 지금 필요한 진행 경로를 선택
- 🧠 **Jev 판독** — 최근 RP를 직접 읽고 관찰·라우팅·실행 문제를 분리 판정
- 🔄 **실제 이행 확인** — “하라고 한 것”이 아니라 실제 출력에서 수행된 변화만 상태에 누적
- 🧍 **캐릭터 / NPC 판독** — 과잉 전문성, 전지적 지식, 비밀 점프, 단일 특성 클리셰화를 억제
- 💬 **OOC 분리** — RP와 OOC를 구분하고, OOC-only 일시정지를 켠 경우 씬 판독과 주입을 중단
- 🌍 **세계관 / 고급 전개** — 발견·수사·위협·사건·관계 등 필요한 전개 요소를 선택적으로 추가
- ⚔️ **갈등 제어** — 싸움 유지, 빌런, 갈등 NPC, 세계 적대성, 유저 불운 등을 별도 관리
- 💾 **채팅별 상태 / 백업** — 관계·사건·인물 상태와 설정을 저장하고 백업·복원

## 🧭 어떻게 작동하나요?

씬판독기는 최근 RP를 직접 읽고, 다음 응답에 필요한 **소수의 실행 지시만** 조립합니다.

~~~mermaid
flowchart TD
    A["💬 최근 RP"] --> B["🔎 Jev 판독"]
    B --> C["🧭 진행 경로 선택"]
    C --> D["🧩 짧은 지시 조립"]
    D --> E["🤖 메인 RP 모델"]
    E --> F["✅ 실제 이행 확인"]
    F --> G["💾 관계·사건 상태 저장"]
~~~

핵심은 **판단과 실행, 실행과 저장을 분리한다는 것**입니다.

- Jev가 “이번 턴에 사건을 진행하자”고 판단해도
- 메인 모델이 실제로 그 행동을 하지 않았다면
- 사건은 진행된 것으로 저장되지 않습니다.

## 📦 설치

씬판독기는 **화면 확장 + Jev 서버 플러그인** 두 부분이 모두 필요합니다.

### 1. SillyTavern 확장 설치

SillyTavern에서:

**Extensions → Install Extension**

을 열고 아래 주소를 입력합니다.

~~~text
https://github.com/bongbong11/-_-.git
~~~

### 2. Jev 서버 플러그인 설치

[서버 플러그인 ZIP](downloads/scene-reader-jev-plugin-v0.4.0.zip)을 받아 압축을 풉니다.

안의 <code>scene-reader-jev</code> 폴더를 다음 위치에 넣습니다.

~~~text
SillyTavern/plugins/scene-reader-jev
~~~

최종적으로 아래 파일이 있어야 합니다.

~~~text
SillyTavern/plugins/scene-reader-jev/package.json
SillyTavern/plugins/scene-reader-jev/index.cjs
~~~

### 3. 서버 플러그인 활성화

<code>config.yaml</code>에서:

~~~yaml
enableServerPlugins: true
~~~

로 설정하고 SillyTavern을 완전히 종료한 뒤 다시 시작합니다.

> [!TIP]
> <code>enableCorsProxy</code>는 켤 필요 없습니다.

<details>
<summary><strong>📱 Android · Termux 설치법 보기</strong></summary>

아래 명령은 SillyTavern을 기본 위치인 `~/SillyTavern`에 설치한 경우입니다. 다른 위치에 설치했다면 `cd` 경로만 실제 SillyTavern 폴더로 바꾸세요.

먼저 실행 중인 SillyTavern을 `Ctrl+C`로 종료한 뒤 Termux에 다음 명령을 한 줄씩 입력합니다.

~~~bash
cd ~/SillyTavern
pkg install curl unzip
curl -L "https://raw.githubusercontent.com/bongbong11/-_-/main/downloads/scene-reader-jev-plugin-v0.4.0.zip" -o "$HOME/scene-reader-jev-plugin-v0.4.0.zip"
mkdir -p plugins
unzip -o "$HOME/scene-reader-jev-plugin-v0.4.0.zip" -d plugins
ls plugins/scene-reader-jev
~~~

마지막 명령의 결과에 `index.cjs`와 `package.json`이 보이면 복사가 끝난 것입니다. 이 플러그인은 별도 패키지가 없으므로 플러그인 폴더에서 `npm install`을 실행할 필요가 없습니다.

Android 브라우저로 ZIP을 이미 내려받았다면 직접 다운로드 명령 대신 다음 방법도 사용할 수 있습니다.

~~~bash
termux-setup-storage
cd ~/SillyTavern
mkdir -p plugins
unzip -o "$HOME/storage/downloads/scene-reader-jev-plugin-v0.4.0.zip" -d plugins
~~~

처음 `termux-setup-storage`를 실행하면 Android의 파일 접근 권한을 허용해야 합니다.

이어서 `config.yaml`을 엽니다.

~~~bash
cd ~/SillyTavern
nano config.yaml
~~~

`enableServerPlugins: true`로 저장한 뒤 `Ctrl+O`, `Enter`, `Ctrl+X` 순서로 nano를 닫고 다시 실행합니다.

~~~bash
cd ~/SillyTavern
bash start.sh
~~~

SillyTavern의 최신 Android·Termux 기본 설치법은 [공식 안내](https://docs.sillytavern.app/installation/android-%28termux%29/)를 참고하세요.

</details>

### 4. Jev 연결

**씬판독기 → 오른쪽 위 톱니바퀴 → Jev API**

에서 API 키를 저장한 뒤 **연결 확인**을 누릅니다.

Jev 주소와 모델은 서버 플러그인에 고정되어 있습니다.

- Upstream API: <code>https://api.typesafe.ai/v1/systemone</code>
- Model: <code>jev-latest</code>

더 자세한 설치와 오류 코드는 [INSTALL.md](INSTALL.md)를 참고하세요.

## 🎛 화면 구성

씬판독기는 크게 네 개의 기능 탭과 설정 화면으로 나뉩니다.

- **자동 전개** — 장면 진행, 관계 방향, 판정 기준, RP 유형, 속도, 사건/NPC 확률
- **고급 전개** — 탐험·발견·수사·위협·공포·암투·관계 등 특별 전개
- **갈등용 진행** — 싸움 유지, 빌런, 갈등 NPC, 세계 적대성, 특별취급 방지 등
- **인물 판정** — 캐릭터·페르소나·NPC 시트 저장과 Jev 경계 판독
- **설정** — Jev 키, 최근 턴 수, 주입 위치, 백업, 초기화 등

## 🎬 자동 전개

자동 전개는 “이번 응답에서 무엇을 실제로 움직일지”를 정합니다.

Jev가 가능한 경로를 판정하면, 씬판독기가 **주진행 1개와 직접 연결되는 보조진행 최대 1개**를 고릅니다. 새 사건 추첨이 실패해도 현재 사건·관계·대화에서 가능한 실행 경로를 다시 찾습니다. 직전 캐릭터 출력이 실제로 진행했는지는 다음 판독에서 확인하며, 계획만으로 관계·사건 상태를 확정하지 않습니다. 판독 상세 화면에는 선택된 경로와 제외 사유가 표시됩니다.

### 판정 기준

- **보수적** — 애매하면 유지하고, 근거 없는 새 진행을 만들지 않음
- **균형** — 현재 흐름 안에서 자연스럽게 한 단계 진행
- **적극적** — 실행 가능한 반응·결정·행동·결과가 있으면 공회전하지 않고 하나를 수행

> [!IMPORTANT]
> **적극적**은 사실 판정을 느슨하게 만드는 설정이 아닙니다.  
> 관계가 없는데 있다고 판단하거나, NPC가 모르는 정보를 알게 만드는 식으로 쓰이지 않습니다.

적극 모드에서도 새 사건을 무조건 만들지는 않습니다. 가능한 기존 흐름이 있다면 다음 순서로 우선합니다.

~~~mermaid
flowchart TD
    A["기존 사건"] --> B["관계 / 갈등 압력"]
    B --> C["현재 상호작용"]
    C --> D["직전 행동의 결과"]
~~~

### RP 진행 유형

- 자연
- 일상
- 모험·임무
- 조사·미스터리
- 위협·생존
- 세력·암투
- 전쟁·작전

진행 유형은 **프리셋의 장르나 문체를 바꾸는 기능이 아닙니다.**  
사건을 어떤 방식으로 움직일지에만 영향을 줍니다.

### 서로 독립적인 속도 설정

- **전체 RP 호흡**
- **관계 진전 속도**
- **사건 해결 속도**

예를 들어 관계는 느리게 진행하면서도, 사건 해결은 빠르게 설정할 수 있습니다.

## ✅ “계획”과 “실제 발생”을 구분합니다

씬판독기가 선택한 경로는 즉시 사실로 저장되지 않습니다.

~~~mermaid
flowchart TD
    A["Jev: 이번 턴 진행 선택"] --> B["Pending Plan"]
    B --> C["메인 모델 출력"]
    C --> D["실제 이행 확인"]
    D --> E["완료 → 상태에 반영<br/>일부 → 수행된 부분만 반영<br/>미이행 → 상태 변경 없음"]
~~~

이 덕분에 메인 모델이 지시를 무시했는데도:

- 관계가 갑자기 진전된 것으로 저장되거나
- 사건 단계가 혼자 앞으로 가거나
- NPC가 등장한 것으로 남는

문제를 줄입니다.

또한 같은 출력의 관계 변화가 재생성·새 USER 반응마다 중복 누적되지 않도록 별도로 관리합니다.

## 🧍 캐릭터 / NPC 판독

인물 판독은 캐릭터를 새로 “창작”하는 기능이 아니라, **시트에서 어디까지 알고 행동할 수 있는지 경계를 잡는 기능**입니다.

### 이런 문제를 줄입니다

- 직업 하나만 보고 모든 관련 분야의 전문가가 됨
- 모델 전체가 아는 비밀을 NPC도 갑자기 알아맞힘
- “blunt”, “cold”, “friendly” 같은 한두 단어를 전 인격으로 확대
- 짧은 시트를 보고 캐릭터를 무능하거나 평범하게 납작하게 만듦
- 한 NPC의 지식이나 접근 권한을 다른 NPC에게 공유

### 짧은 시트도 얕게 분석하지 않습니다

씬판독기는 짧은 NPC 시트를 빈칸 채우기용 재료로 보지 않습니다.

저장할 때는 대략 다음 경계를 구조화합니다.

- **명시 근거** — 시트에 실제로 적힌 역할·성향·관계·동기·기술
- **역할 범위** — 직업·관계상 자연스럽게 가능한 추론 범위
- **지식 / 접근 상한** — 전문지식·비밀·기록·권한에 필요한 근거
- **성향 적용 범위** — 특정 성향이 어떤 상황에서 드러나는지
- **Sparse 여부** — 정보 부족을 평범함·무능함으로 오인하지 않도록 표시

그리고 매턴에는 현재 장면과 주제에 맞춰 **활성 인물별로 따로** 판정합니다.

- 장면 역할: 부재 / 배경 유지 / 실제 실행
- 현재 주제의 지식 근거·능력·접근·확실성
- 이번 장면에 실제로 적용할 성향·응답 방식·과거 영향

인물 탭의 **저장된 기본 경계**는 시트를 저장할 때 만든 참고값이며, 매턴의 결론이 아닙니다. 실제 현재 장면 결과는 **이번 턴 인물 판정**에서 인물별로 확인할 수 있습니다. 이름이 반복되지 않은 연속 장면에서는 직전 판정의 참여 인물을 후보로 이어가고, 부재가 확인되면 다음 후보에서 제외합니다.

### 비밀 지식은 근거가 필요합니다

직감이나 눈치는 “뭔가 이상하다” 정도의 의심은 만들 수 있지만, 근거 없이 다음을 정확히 맞히는 우회로로 사용하지 않습니다.

- 숨겨진 관계
- 정확한 원인
- 범인
- 비밀의 구체적인 내용
- 다른 인물의 내면이나 계획

> 모델이 알고 있는 정보와 **그 NPC가 실제로 알고 있는 정보는 다릅니다.**

## 👀 원본 시트를 메인 모델도 보고 있나요?

씬판독기는 원본 시트의 노출 여부에 따라 주입량을 다르게 처리합니다.

- **원본 시트를 이미 보는 인물** — 이번 턴에 필요한 지식·행동 경계만 주입
- **씬판독기에만 저장한 인물** — 핵심 역할·관계·성향과 이번 턴 경계를 함께 주입

- SillyTavern이 원래 제공하는 캐릭터·페르소나 자료는 기본적으로 이미 보이는 자료로 취급합니다.
- 씬판독기에만 직접 넣은 NPC 시트는 메인 모델이 모르는 자료로 취급합니다.
- 별도 로어북 등에 넣은 자료는 필요에 따라 설정할 수 있습니다.

## 💬 OOC 처리

OOC를 RP 속에서 실제로 일어난 사건처럼 읽지 않습니다.

- **RP only** — RP를 장면 근거로 판독한 뒤 다음 RP를 생성
- **RP + OOC** — RP는 관찰 근거로, OOC는 이번 진행의 방향·제약으로 분리
- **OOC only** — Jev 판독과 씬 주입을 건너뛰고 OOC 응답만 처리. 설정에서 OOC 건너뜀 알림을 켜면 토스트도 표시

설정의 **검사용 OOC** 버튼을 누른 뒤 OOC-only 메시지를 보내면, 직전 씬판독기 주입문을 그 응답에만 그대로 유지합니다. 검사용 응답은 RP 이행 검증이나 관계·사건 상태 누적에 사용하지 않습니다.

지원하는 일반 형식:

~~~text
(OOC: ...)
[OOC: ...]
~~~

대소문자와 여러 블록, multiline OOC를 처리합니다.

### OOC_CHAT 연동

OOC_CHAT이 USER 메시지에:

~~~text
extra.ooc_chat = true
~~~

를 남기면 이 표식을 텍스트 정규식보다 우선하는 확정 OOC 신호로 사용합니다.

- 실제 OOC 본문은 메시지의 <code>mes</code>에서 읽음
- <code>extra.ooc_instruction</code>은 OOC 본문으로 사용하지 않음
- OOC-only에서는 Jev 씬 판독과 기존 씬 주입을 건너뜀

## 🌍 세계관

### 프리셋 기본 세계관 사용

별도 세계관 전문을 주입하지 않고 현재 프리셋과 로어북 설정을 그대로 사용합니다.

씬판독기는 **진행 방향만 보조**합니다.

### 내장 / 커스텀 세계관

세계관은 고급 전개와 별개로 하나만 선택합니다.

커스텀 세계관은:

- 이름
- 주입 전문
- 원작·프랜차이즈 세계 여부

만 저장하면 됩니다.

Jev 라우팅용 짧은 힌트는 로컬에서 자동 생성하므로 별도 모델 호출은 필요하지 않습니다.

원작·프랜차이즈 세계를 켜면 NPC가 필요할 때 현재 위치·시대·역할에 자연스럽게 맞는 원작 인물도 후보로 판정합니다. 커스텀 세계관은 추가·수정·삭제·JSON 복사·가져오기를 지원합니다.

## 🌒 고급 전개

고급 전개는 현재 장면과 맞을 때만 특별한 전개 요소를 엽니다.

지원 범주:

- 일상·교류
- 탐험·발견
- 사건·목표
- 추리·수사
- 위협·전투
- 공포·초자연
- 암투·공작
- 관계·치정

전개 개방도:

| 단계 | 새 고급 전개 기회 |
|---|---:|
| 보수적 | 18% |
| 균형 | 35% |
| 적극적 | 58% |
| 매우 적극적 | 75% |

고급 전개가 켜져 있으면 기본 RP 진행의 새 사건 생성은 잠시 비활성화되지만:

- 관계 판정
- RP 호흡
- NPC 지식
- 사건 해결 속도
- 갈등용 진행

은 계속 함께 작동합니다.

고급 사건은 하나만 유지하며 자동으로 새 사건으로 갈아치우지 않습니다.  
필요하면 현황판에서 **사건 끝내기**를 눌러 다음 기회를 엽니다.

## ⚔️ 갈등용 진행

갈등 장면에서 필요한 기능만 선택적으로 켤 수 있습니다.

- 부정 편향 최우선
- 싸움 유지
- 빌런 자동
- 갈등 속 NPC 활성화
- 세계 적대성
- NPC 특별취급 방지
- 유저 불운

기존 갈등용 빠답 원문은 보존하며, 씬판독기는 전체 우선순위 안에서 필요한 블록만 조립합니다.

## 🎲 사건 / NPC / 빌런 확률

확률은 **새로 만드는 것**에만 적용됩니다.

| 대상 | 확률 적용 |
|---|---|
| 새 사건 | ✅ |
| 새 일반 NPC | ✅ |
| 새 빌런 | ✅ |
| 이미 존재하는 사건 진행 | ❌ |
| 기존 NPC 행동 | ❌ |
| 현재 대화에 대한 직접 반응 | ❌ |
| 관계 압력 / 직전 행동 결과 | ❌ |

같은 장면에서 실패한 추첨을 계속 반복하지 않으며, 재생성에서는 기존 판정과 추첨을 재사용합니다.

## 🧩 최종 주입은 짧게

씬판독기는 가능한 모든 기능을 한 번에 집어넣지 않습니다.

한 응답에서 행동성 지시는 기본적으로:

~~~text
주 경로 1개
+
직접 종속된 보조 경로 최대 1개
~~~

만 유지합니다.

지속적인 세계·관계·지식 경계 같은 hard constraint는 필요할 때 별도로 함께 적용됩니다.

## 🔄 수정 · 삭제 · 스와이프 · 재생성

씬판독기는 채팅이 수정됐을 때 이전 판정을 무조건 믿지 않습니다.

다음이 바뀌면 관련 판정을 무효화합니다.

- 최신 USER 입력
- recentTurns 안의 이전 USER / CHARACTER 메시지
- OOC
- 캐릭터 / NPC 시트
- 세계관 힌트

반면 같은 출력의 swipe / regenerate는 저장된 판정과 추첨을 재사용해 중복 누적을 막습니다.

캐릭터 출력 자체를 수정·삭제하면 해당 출력 때문에 확정됐던 관계·사건·NPC 상태도 가능한 범위에서 이전 상태로 복구합니다.

## 🔎 판독 범위

씬판독기가 읽는 범위는 제한되어 있습니다.

- 최근 화면상 RP **1~5턴**
- 이 채팅에서 확장이 저장한 관계·사건·생성 NPC 상태
- 활성 인물의 관련 시트 근거
- 명시적으로 제공된 세계관 힌트

한 턴은 USER 입력에서 시작해 뒤따르는 CHARACTER 출력까지입니다.

매우 긴 기록은 최신 내용을 우선합니다.

> [!IMPORTANT]
> 씬판독기는 숨겨진 기억, 프리셋 전체, 로어북 전체를 마음대로 읽고 해석하는 구조가 아닙니다.

NSFW 장면도 최근 RP로 읽을 수 있지만, **성적 장면 자체의 진행·완화·중단·종료 여부를 판정 축으로 사용하지 않습니다.**

## 🧠 인물 판정을 사용할 때 기존 프롬프트와의 관계

필요한 캐릭터 / NPC 시트를 씬판독기에 저장하고 **인물 판정 사용**을 켰다면, 중복을 피하기 위해 프리셋의 다음 계열 프롬프트를 끌 수 있습니다.

- <code>CHARACTER_KNOWLEDGE_AND_CONTEXT</code>
- <code>ACTIVE_HISTORY</code>
- <code>CANON_NPC_POLICY</code>

단:

- 인물 판정을 끈 경우
- 필요한 시트를 저장하지 않은 경우

에는 기존 프롬프트를 유지하는 편이 안전합니다.

세계관·문체·장면 연속성 프롬프트는 인물 판정의 대체 대상이 아닙니다.

## 🧰 문제 해결

- **404** — 서버 플러그인 설치 위치와 SillyTavern 재시작 확인
- **401 / 403** — Jev 키 저장·인증 확인
- **502 / 시간 초과** — SillyTavern 서버에서 TypeSafe Jev 연결 여부 확인
- **씬판독기 메뉴가 안 보임** — 확장 설치 후 새로고침 또는 SillyTavern 재시작
- **매크로가 적용되지 않음** — 주입 위치 설정이 `macro`인지, 프리셋에 매크로가 한 번만 들어갔는지 확인
- **같은 내용이 두 번 주입됨** — `depth`와 `macro`를 동시에 수동으로 중복 배치하지 않았는지 확인
- **NPC가 원본 성격을 모름** — 해당 NPC 시트가 메인 모델에도 보이는지 또는 씬판독기에 올바르게 저장됐는지 확인
- **OOC인데 씬 지시가 섞임** — OOC 형식 또는 OOC_CHAT의 <code>extra.ooc_chat=true</code> 유지 여부 확인

자세한 설치 오류는 [INSTALL.md](INSTALL.md)를 참고하세요.

<summary><strong>🔬 내부 판정 구조를 조금 더 자세히 보기</strong></summary>

### 판정 종류

Jev 판정은 내부적으로 크게 다음 성격으로 분리됩니다.

- **Observation** — 장면에서 실제로 확인할 수 있는 사실
- **Routing** — 다음 응답에서 어떤 경로를 선택할지
- **Diagnostic** — 최근 응답의 실행 문제
- **Verification** — 직전 계획을 메인 모델이 실제로 수행했는지

보수적 / 균형 / 적극적 설정은 routing에만 영향을 주며, 사실·지식 판정 기준을 느슨하게 만들지 않습니다.

### none / unclear / not_applicable

- <code>none</code> — 관련 신호가 없다는 근거가 있음
- <code>unclear</code> — 신호는 있지만 분류가 불확실함
- <code>not_applicable</code> — 해당 판정 자체가 현재 상황에 적용되지 않음

현재 턴의 <code>none</code>이나 <code>unclear</code>가 이전에 확정된 persistent 상태를 자동으로 지우지 않습니다.

### 최종 흐름

~~~mermaid
flowchart TD
    A["최근 메시지 선택"] --> B["RP / OOC 분리"]
    B --> C["Jev 판정"]
    C --> D["Policy"]
    D --> E["Coordinator"]
    E --> F["확률 / 제약"]
    F --> G["Action Budget"]
    G --> H["최종 Injection"]
    H --> I["Main Output"]
    I --> J["Verification"]
    J --> K["Persistent Commit"]
~~~
