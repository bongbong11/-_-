## ✨ 이 확장으로 뭘 할 수 있나요?

씬판독기는 단순한 “다음 전개 추천기”가 아닙니다.

- 🎬 **장면 자동 전개** — 관계, 사건, NPC, 직접 반응 중 지금 필요한 축을 골라 실제로 한 단계 움직입니다.
- 🎲 **사건 자동 추첨** — 진행 유형에 맞는 사건을 뽑고, 목표·압박·해결 조건까지 함께 관리합니다.
- 🧑‍🤝‍🧑 **NPC 자동 추첨** — 역할·목적·능력·신뢰성·제약·등장 방식이 다른 NPC를 장면에 맞춰 생성합니다.
- 😈 **빌런 자동 추첨** — 접근 방식·동기·수단·영향력·능력·태도가 다른 갈등 인물을 생성하고 유지합니다.
- 💞 **관계 변화 판독** — 가까워짐/멀어짐뿐 아니라 신뢰·친밀감·로맨스 근거와 관계 비트를 따로 추적합니다.
- 🧯 **정체·반복 교정** — 망설임, 질문만 던지기, 같은 말 반복, 행동 회피, 장면 조기 종료 등을 잡아냅니다.
- 🌒 **고급 전개** — 탐험·수사·위협·공포·암투·치정 같은 전개를 별도 사건표에서 꺼내 씁니다.
- 🧍 **캐릭터/NPC 지식 경계 판독** — 갑자기 전문가가 되거나 모를 비밀을 알아맞히는 일을 줄입니다.
- 💬 **OOC 분리** — RP와 OOC를 구분하고 OOC-only에서는 필요 시 씬 판독과 주입을 멈춥니다.
- 💾 **채팅별 상태·백업** — 관계, 사건, NPC, 빌런, 설정, 시트와 판독 상태를 채팅별로 유지합니다.

## 🧭 작동 흐름

씬판독기는 최근 RP를 **직접 읽고**, 다음 응답에 필요한 소수의 실행 지시만 조립합니다.

~~~mermaid
flowchart TD
    A["💬 최근 RP"] --> B["🔎 Jev 판독"]
    B --> C["🧭 이번 턴의 주 경로 선택"]
    C --> D["🎲 필요하면 사건·NPC·빌런 추첨"]
    D --> E["🧩 짧은 실행 지시 조립"]
    E --> F["🤖 메인 RP 모델"]
    F --> G["✅ 실제 이행 확인"]
    G --> H["💾 수행된 변화만 상태 저장"]
~~~

핵심은 **판정 → 실행 → 확인 → 저장**을 나누는 것입니다.

> Jev가 “이번 턴에 사건을 진행하자”고 선택했더라도, 메인 모델이 실제 출력에서 그 행동을 하지 않았다면 사건은 진행된 것으로 저장되지 않습니다.

# 📦 설치

씬판독기는 **화면 확장 + Jev 서버 플러그인** 두 부분이 모두 필요합니다.

## 1. SillyTavern 확장 설치

SillyTavern에서 **Extensions → Install Extension**을 열고 아래 주소를 입력합니다.

~~~text
https://github.com/bongbong11/-_-.git
~~~

## 2. Jev 서버 플러그인 설치

[서버 플러그인 ZIP](downloads/scene-reader-jev-plugin-v0.4.0.zip)을 받아 압축을 풉니다.

안의 <code>scene-reader-jev</code> 폴더를:

~~~text
SillyTavern/plugins/scene-reader-jev
~~~

에 넣습니다.

최종적으로 아래 파일이 있어야 합니다.

~~~text
SillyTavern/plugins/scene-reader-jev/package.json
SillyTavern/plugins/scene-reader-jev/index.cjs
~~~

## 3. 서버 플러그인 활성화

<code>config.yaml</code>:

~~~yaml
enableServerPlugins: true
~~~

설정 후 SillyTavern을 완전히 종료했다가 다시 시작합니다.

> [!TIP]
> <code>enableCorsProxy</code>는 켤 필요 없습니다.

<details>
<summary><strong>📱 Android · Termux 설치법 보기</strong></summary>

아래 명령은 SillyTavern을 기본 위치인 <code>~/SillyTavern</code>에 설치한 경우입니다.

먼저 실행 중인 SillyTavern을 <code>Ctrl+C</code>로 종료한 뒤:

~~~bash
cd ~/SillyTavern
pkg install curl unzip
curl -L "https://raw.githubusercontent.com/bongbong11/-_-/main/downloads/scene-reader-jev-plugin-v0.4.0.zip" -o "$HOME/scene-reader-jev-plugin-v0.4.0.zip"
mkdir -p plugins
unzip -o "$HOME/scene-reader-jev-plugin-v0.4.0.zip" -d plugins
ls plugins/scene-reader-jev
~~~

마지막 결과에 <code>index.cjs</code>와 <code>package.json</code>이 보이면 복사가 끝난 것입니다.

브라우저로 ZIP을 이미 받았다면:

~~~bash
termux-setup-storage
cd ~/SillyTavern
mkdir -p plugins
unzip -o "$HOME/storage/downloads/scene-reader-jev-plugin-v0.4.0.zip" -d plugins
~~~

이어서:

~~~bash
cd ~/SillyTavern
nano config.yaml
~~~

에서 <code>enableServerPlugins: true</code>로 바꾸고 저장한 뒤 다시 실행합니다.

~~~bash
cd ~/SillyTavern
bash start.sh
~~~

SillyTavern의 최신 Android·Termux 기본 설치법은 [공식 안내](https://docs.sillytavern.app/installation/android-%28termux%29/)를 참고하세요.

</details>

## 4. Jev 연결

**씬판독기 → 오른쪽 위 톱니바퀴 → Jev API**

에서 API 키를 저장하고 **연결 확인**을 누릅니다.

- Upstream API: <code>https://api.typesafe.ai/v1/systemone</code>
- Model: <code>jev-latest</code>

더 자세한 설치와 오류 코드는 [INSTALL.md](INSTALL.md)를 참고하세요.

# 🚀 3분 빠른 시작

1. 마법봉 메뉴에서 **씬판독기**를 엽니다.
2. ⚙️에서 Jev API 키를 저장하고 **연결 확인**을 누릅니다.
3. **생성 직전에 자동 판독**을 켭니다.
4. **세계 반응 방향 / 관계 방향 / 판정 기준 / RP 진행 유형**을 고릅니다.
5. **전체 RP 호흡 / 관계 진전 속도 / 사건 해결 속도**를 조절합니다.
6. 원하는 경우 **공통 인물 등장 확률 / 새 사건 발생 확률**을 바꿉니다.
7. 이후에는 평소처럼 채팅합니다.

> [!TIP]
> 처음에는 **세계 반응: 자연스럽게 / 관계: 상황에 따라 변화 / 판정: 균형 / 진행: 자연 진행** 정도로 시작해도 충분합니다.

# 🎬 자동 전개

## 세계 반응 방향

프리셋의 장르나 문체는 그대로 두고, **유저를 향한 세계의 기본 반응 방향**만 정합니다.

- 자연스럽게
- 긍정적으로
- 적대적으로

## 캐릭터 → 유저 관계 방향

세계 반응과 별개입니다.

- 상황에 따라 변화
- 호의적
- 적대적

선택한 방향은 기본 방향으로 유지하고, Jev는 매턴 **실제 관계 변화가 있었는지와 그 크기**를 따로 판정합니다.

## 판정 기준

- **보수적** — 명확한 진행 근거가 있을 때 움직임
- **균형** — 현재 흐름 안에서 자연스러운 한 단계를 선택
- **적극적** — 실행 가능한 행동·반응·결과가 있으면 공회전하지 않고 하나를 확실히 수행

> [!IMPORTANT]
> **적극적**은 사실 판정을 느슨하게 만드는 옵션이 아닙니다.  
> 관계가 없는데 있다고 판단하거나, NPC가 모르는 사실을 알게 만드는 식으로 쓰이지 않습니다.

## RP 진행 유형

- 사용 안 함
- 자연 진행
- 일상·생활 진행
- 모험·임무 진행
- 조사·미스터리 진행
- 위협·생존 진행
- 세력·암투 진행
- 전쟁·작전 진행

이 설정은 **장르나 문체가 아니라 사건이 움직이는 방식**을 정합니다.

## 서로 독립적인 세 가지 속도

- **전체 RP 호흡** — 반복·연결부를 얼마나 압축하고 중요한 순간을 얼마나 오래 붙잡을지
- **관계 진전 속도** — 관계 변화가 어느 정도 근거가 쌓였을 때 허용될지
- **사건 해결 속도** — 사건이 언제 부분 해결/실질 해결로 넘어갈지

관계는 느리게, 사건은 빠르게처럼 서로 다르게 설정할 수 있습니다.

# 🎲 사건 · NPC · 빌런 자동 추첨

이 부분은 씬판독기의 핵심 기능 중 하나입니다.

씬판독기는 무작정 랜덤을 굴리지 않습니다.

~~~mermaid
flowchart TD
    A["Jev가 새 요소가 필요한지 판정"] --> B{"새 요소가 필요함?"}
    B -->|"아니오"| C["기존 장면·인물 계속 사용"]
    B -->|"예"| D{"설정 확률 통과?"}
    D -->|"실패"| E["같은 기회에서 재추첨하지 않음"]
    D -->|"통과"| F["사건 / 일반 NPC / 빌런 프로필 생성"]
    F --> G["메인 모델에 실제 등장·실행 지시"]
    G --> H["출력에서 수행됐는지 확인"]
    H --> I["수행된 항목만 확정 저장"]
~~~

## 🎬 사건 자동 추첨

진행 유형별로 다른 사건표를 사용합니다.

예를 들어:

- 자연 진행 → 이전 약속의 결과, 실용적 기회, 이전 선택의 후속 반응
- 일상 → 일정 충돌, 생활권 문제, 엇갈린 연락, 작은 성취
- 조사 → 단서·증언·용의자·정보 접근과 관련된 사건
- 위협·생존 → 위험·대피·자원·접근 경로와 관련된 사건
- 세력·암투 / 전쟁·작전 → 조직, 권한, 정보, 작전 단계에 맞는 사건

뽑힌 사건에는 단순 제목만 있는 것이 아니라:

- **계기**
- **목표**
- **압박**
- **해결 조건**
- **실제 실행 지시**

가 함께 들어갑니다.

사건은 한 번 생성되면 저장되어 **계속 진행 / 종료 / 교체**될 수 있습니다.

## 🧑‍🤝‍🧑 일반 NPC 자동 추첨

새 NPC가 필요하다고 판정되면 진행 유형에 맞는 역할에서 하나를 고르고, 다음 요소를 조합합니다.

- 역할
- 현재 장면에 접근 가능한 이유
- 개인 목적
- 장면에서 제공하는 기능
- 영향력
- 능력 수준
- 태도
- 신뢰성
- 이해관계
- 제약
- 입장 변화 조건
- 등장 방식
- 장면에 머무는 기간

즉 “행인 A”를 만드는 대신 **현재 장면에서 왜 여기 있고, 무엇을 원하고, 어디까지 할 수 있는지**가 함께 정해집니다.

기존 NPC가 적합하면 새로 만들지 않고 재사용할 수 있으며:

- 재사용
- 배경으로 전환
- 퇴장
- 교체 추첨

도 가능합니다.

## 😈 빌런 자동 추첨

갈등 장면에서 빌런 자동이 켜져 있고 실제 개입이 필요하다고 판정되면:

- 접근 방식
- 영향력 / 레버리지
- 동기
- 방해 수단
- 능력 수준
- 태도·감정 통제 방식

을 조합해 갈등 인물을 만듭니다.

빌런도 일회용이 아니라 **유지 / 종료 / 교체**될 수 있고, UI에서 **현재 빌런 종료 · 새 추첨 대기**를 직접 누를 수 있습니다.

## 확률은 새로 만드는 것에만 적용

| 대상 | 확률 |
|---|---|
| 새 사건 | ✅ |
| 새 일반 NPC | ✅ |
| 새 빌런 | ✅ |
| 이미 있는 사건 진행 | ❌ |
| 기존 NPC 행동·재등장 | ❌ |
| 현재 대화에 대한 직접 반응 | ❌ |
| 관계 압력 / 직전 행동의 결과 | ❌ |

**공통 인물 등장 확률**은 새 일반 NPC와 새 빌런에 함께 적용됩니다.

선택값:

<code>5% / 10% / 20% / 35% / 50% / 100%</code>

100%는 “아무 때나 무조건 생성”이 아니라 **Jev가 새 인물이 필요하다고 판정한 다음 적합한 기회에서 확정**입니다.

새 사건 발생 확률도 같은 방식으로 동작합니다.

# 💞 관계 판독과 관계 비트

씬판독기는 “호감도 숫자” 하나로 관계를 처리하지 않습니다.

매턴 실제 RP에서:

- 가까워짐 / 멀어짐 / 유지
- 신뢰 증가·감소
- 친밀감 증가·감소
- 단순 끌림인지 실제 로맨스 근거인지
- 기존 상태와 비교해 실제 변화가 있었는지

를 분리해서 봅니다.

필요할 때 다음 관계 비트 중 하나를 선택할 수 있습니다.

- 회피·미루기
- 거절·경계 설정
- 고백·직접 공개
- 속마음과 행동의 불일치
- 취약성·신뢰 공개
- 질투·마찰
- 회복·화해 시도
- 관계를 바꾸는 선택

현재 턴에 <code>none</code>이 나왔다고 이전에 쌓인 관계 상태가 사라지지는 않습니다.

# 🧯 반복·정체·실행 회피 교정

씬판독기는 사건만 만드는 확장이 아닙니다.  
**지금 장면이 왜 안 움직이는지도 따로 판독합니다.**

다음과 같은 문제를 잡습니다.

- 지나친 망설임 때문에 행동이 계속 미뤄짐
- 거절만 반복하며 상호작용이 정체됨
- 같은 대화 내용을 돌려 말함
- 캐릭터가 질문만 던지고 자기 행동은 하지 않음
- 유저 입력을 다시 요약·에코함
- 비슷한 종결 문장을 계속 반복함
- 해야 할 행동을 분위기나 말로만 얼버무림
- 행동이 일어나기 직전에 장면을 끊거나 생략함
- 직전 턴에서 선택된 지시를 실제로 수행하지 않음

판독된 문제가 있으면 **이번 응답의 주 행동과 충돌하지 않는 범위에서 필요한 교정만** 붙입니다.

# ✅ 계획과 실제 발생을 구분

~~~mermaid
flowchart TD
    A["이번 턴 실행 계획"] --> B["Pending Plan"]
    B --> C["메인 모델 출력"]
    C --> D{"실제로 수행했나?"}
    D -->|"완료"| E["상태에 반영"]
    D -->|"일부"| F["수행된 부분만 반영"]
    D -->|"미이행"| G["상태 변경 없음"]
~~~

덕분에:

- 모델이 사건을 진행하지 않았는데 사건 단계만 올라가거나
- NPC가 실제로 등장하지 않았는데 등장한 것으로 남거나
- 관계 변화가 말만 있었는데 확정되는

문제를 줄입니다.

같은 출력의 관계 변화가 재생성이나 새 USER 반응 때 중복 누적되지 않도록 별도로 관리합니다.

# 🌒 고급 전개

고급 전개는 기본 사건 생성과 별도의 전개 시스템입니다.

사용할 수 있는 요소:

- 일상·교류
- 탐험·발견
- 사건·목표
- 추리·수사
- 위협·전투
- 공포·초자연
- 암투·공작
- 관계·치정

## 전개 개방도

| 단계 | 새 고급 전개 기회 |
|---|---:|
| 보수적 | 18% |
| 균형 | 35% |
| 적극적 | 58% |
| 매우 적극적 | 75% |

Jev가 현재 장면에 들어올 수 있는 원인·접근 경로가 있다고 판정한 **적합한 기회에서만** 한 번 굴립니다.

고급 전개가 켜져 있으면 기본 RP 진행의 새 사건 생성은 잠기지만:

- 관계 판정
- 전체 호흡
- NPC 지식 판정
- 사건 해결 속도
- 갈등용 진행

은 그대로 함께 작동합니다.

## 고급 사건에 필요한 인물·집단·존재도 생성

고급 사건이 사람이나 집단을 필요로 하면 별도의 엔티티를 생성할 수 있습니다.

- 역할/형태
- 목적
- 이해관계
- 제약

을 가지며, 이미 같은 세계·요소에 적합한 저장 인물이 있다면 **새로 뽑지 않고 재사용**할 수도 있습니다.

고급 사건은 하나만 유지하며, 필요하면 현황판에서 **사건 끝내기**를 눌러 다음 사건 기회를 열 수 있습니다.

# ⚔️ 갈등용 진행

갈등용 진행 탭은 필요한 것만 선택적으로 켤 수 있습니다.

## 부정 편향 최우선

켜면 이 탭에서 활성화된 갈등용 지시를 관계·사건·NPC·속도 지시보다 우선합니다.

## 싸움 유지

실제로 진행 중인 대치·싸움이 있을 때만 적용합니다.  
긴장만 있다는 이유로 싸움을 새로 만들지는 않습니다.

## 빌런 자동

현재 장면에 갈등 인물이 필요할 때 빌런을 생성·유지·종료·교체합니다.

## 갈등 속 NPC 활성화

NPC가 실제로 참여 중이거나 이번 응답에 등장할 때, 자기 목적과 이해관계에 따라 움직이도록 합니다.

## 세계·관계 편향

- 세계 적대성
- NPC 특별취급 방지
- 유저 불운

이 항목들은 켜져 있을 때 IC 응답에 지속 적용되며 OOC 응답에는 주입하지 않습니다.

# 🧍 인물 판정

인물 판정은 캐릭터를 새로 창작하는 기능이 아니라, **시트에서 어디까지 알고 행동할 수 있는지 경계를 잡는 기능**입니다.

저장할 수 있는 시트:

- 캐릭터
- 페르소나
- NPC

매턴 모든 시트를 전부 넣지 않고, **현재 장면과 관련 있는 활성 인물 최대 3명**만 골라 판정합니다.

## 이런 문제를 줄입니다

- 직업 하나만 보고 모든 관련 분야의 전문가가 됨
- 모델 전체가 아는 비밀을 NPC도 갑자기 알아맞힘
- 한두 성격 단어를 전 인격으로 확대
- 짧은 시트를 보고 무능하거나 평범한 인물로 납작하게 만듦
- 한 NPC의 지식·권한을 다른 NPC에게 복사

저장할 때는 대략 다음 경계를 구조화합니다.

- **명시 근거** — 실제 시트에 적힌 역할·관계·성향·동기·기술
- **역할 범위** — 직업·관계상 자연스럽게 가능한 범위
- **지식 / 접근 상한** — 전문 정보·비밀·기록·권한에 필요한 근거
- **성향 적용 범위** — 한 특성을 모든 상황으로 확대하지 않도록 제한
- **Sparse 여부** — 정보가 적다는 이유로 평범함·무능함을 가정하지 않음

> 모델이 알고 있는 정보와 **그 NPC가 실제로 알고 있는 정보는 다릅니다.**

## 원본 시트가 메인 모델에도 보이는 경우

- 이미 캐릭터 카드·페르소나·활성 로어북으로 보이는 시트 → 이번 턴에 필요한 경계만 주입
- 씬판독기에만 저장된 NPC 시트 → 핵심 역할·관계·성향 + 이번 턴 경계를 함께 주입

# 💬 OOC 처리

OOC를 RP에서 실제로 일어난 사실로 읽지 않습니다.

- **RP only** → RP를 장면 근거로 판독
- **RP + OOC** → RP는 관찰 근거, OOC는 이번 진행의 방향·제약
- **OOC only** → <code>OOC-only 입력에서는 판독·주입 일시정지</code>가 켜져 있으면 Jev 판독을 건너뛰고 기존 씬 주입을 제거

지원 형식:

~~~text
(OOC: ...)
[OOC: ...]
~~~

대소문자, 여러 블록, multiline OOC를 처리합니다.

## OOC_CHAT 연동

<code>extra.ooc_chat = true</code>가 있으면 일반 텍스트 정규식보다 우선하는 확정 OOC 신호로 사용합니다.

- 실제 OOC 본문은 메시지의 <code>mes</code>에서 읽음
- <code>extra.ooc_instruction</code>은 OOC 본문으로 사용하지 않음
- OOC-only 일시정지 옵션이 켜진 경우 씬 판독과 기존 주입을 건너뜀

# 🌍 세계관 관리

## 프리셋 기본 세계관 사용

별도 세계관 전문을 주입하지 않고 현재 프리셋과 로어북 설정을 그대로 사용합니다.

## 내장 / 커스텀 세계관

세계관은 한 번에 하나만 선택합니다.

커스텀 세계관 관리에서:

- 새 세계관 추가
- 이름 수정
- Jev 판정용 짧은 힌트 작성
- 주입 전문 저장
- 삭제
- 전체 JSON 복사
- JSON 가져오기

를 할 수 있습니다.

Jev 판정 힌트를 비워두면 세계관 전문에서 짧은 힌트를 로컬로 자동 생성합니다.

세계관 전문은 Jev에 그대로 보내지 않고, 실제 최종 프리셋 주입용으로만 사용할 수 있습니다.

- 같은 관계 변화가 중복 누적되는 문제
- 같은 장면에서 확률을 계속 다시 굴리는 문제

를 줄입니다.

캐릭터 출력 자체를 수정·삭제하면 그 출력 때문에 확정됐던 관계·사건·NPC 상태도 가능한 범위에서 이전 상태로 복구합니다.

# 🔎 판독 범위

씬판독기가 읽는 범위는 제한되어 있습니다.

- 최근 화면상 RP **1~5턴**
- 이 채팅에서 확장이 저장한 관계·사건·NPC·빌런 상태
- 활성 인물의 관련 시트 근거
- 명시적으로 제공된 세계관 힌트

한 턴은 USER 입력에서 시작해 뒤따르는 CHARACTER 출력까지입니다.

매우 긴 기록은 최신 내용을 우선합니다.

> [!IMPORTANT]
> 씬판독기는 숨겨진 기억, 프리셋 전체, 로어북 전체를 마음대로 읽고 해석하는 구조가 아닙니다.

NSFW 장면도 최근 RP로 읽을 수 있지만, **성적 장면 자체의 진행·완화·중단·종료 여부를 판정 축으로 사용하지 않습니다.**

# 🧠 인물 판정을 사용할 때 기존 프롬프트와의 관계

필요한 캐릭터 / NPC 시트를 씬판독기에 저장하고 **인물 판정 사용**을 켰다면, 중복을 피하기 위해 프리셋의 다음 계열 프롬프트를 끌 수 있습니다.

- <code>CHARACTER_KNOWLEDGE_AND_CONTEXT</code>
- <code>ACTIVE_HISTORY</code>
- <code>CANON_NPC_POLICY</code>

단, 인물 판정을 끄거나 필요한 시트를 저장하지 않았다면 기존 프롬프트를 유지하는 편이 안전합니다.

세계관·문체·장면 연속성 프롬프트는 인물 판정의 대체 대상이 아닙니다.

# 🧰 문제 해결

| 증상 | 확인할 것 |
|---|---|
| **404** | 서버 플러그인 설치 위치와 SillyTavern 재시작 |
| **401 / 403** | Jev 키 저장·인증 |
| **502 / 시간 초과** | SillyTavern 서버에서 TypeSafe Jev 연결 가능 여부 |
| 씬판독기 메뉴가 안 보임 | 확장 설치 후 새로고침 또는 SillyTavern 재시작 |
| 매크로가 적용되지 않음 | 주입 위치가 macro인지, 프리셋에 매크로가 한 번만 들어갔는지 |
| 같은 내용이 두 번 주입됨 | depth와 macro를 동시에 중복 배치하지 않았는지 |
| NPC가 원본 성격을 모름 | NPC 시트가 메인 모델에도 보이는지 또는 씬판독기에 올바르게 저장됐는지 |
| OOC인데 씬 지시가 섞임 | OOC 형식 또는 OOC_CHAT의 <code>extra.ooc_chat=true</code> 유지 여부 |

자세한 설치 오류는 [INSTALL.md](INSTALL.md)를 참고하세요.

Jev 판정은 내부적으로 크게 다음 성격으로 나뉩니다.

- **Observation** — 장면에서 실제로 확인할 수 있는 사실
- **Routing** — 다음 응답에서 어떤 경로를 선택할지
- **Diagnostic** — 최근 응답의 실행 문제
- **Verification** — 직전 계획을 메인 모델이 실제로 수행했는지

보수적 / 균형 / 적극적 설정은 routing에만 영향을 주며 사실·지식 판정 기준을 느슨하게 만들지 않습니다.
